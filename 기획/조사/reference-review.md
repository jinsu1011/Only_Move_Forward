# 참고자료 검토

## 제출 기준과 충돌

|항목|9반 평가 기준|일반 과제 안내|적용|
|---|---|---|---|
|마감|2026-09-17 13:40|3일차 13:30|9반 13:40. 작업 완료 목표는 13:30|
|지각|당일 지각 15점, 다음날 이후 10점, 누락 0점|지각 납기 0점|9반 차등 기준|
|파일명|반_고유번호_이름_프로젝트명|고유번호 없음|9반 형식|
|발표|마감 후, 5분, 4:30–5:00 목표|14:30 안내|9반 기준|

9반 문서가 사용자 지정 최상위 출처이므로 적용한다. 세 파일 중 마지막 업로드 시각이 제출 완료 시각이다. 별도 발표 슬라이드보다 개요 PDF를 발표에 사용한다.

필수 파일명: `{반}_{고유번호}_{이름}_{프로젝트명}-개요.pdf`, `-API.yml`, `-DB.dbml`.
반은 9반 자료에 근거한다. 고유번호 및 제출 이름은 최종 파일명 작성 전 사용자 확인 대상이며 추측하지 않는다.

## 실제 읽은 자료와 적용

- 평가 PDF 8쪽: 텍스트 추출 글자 깨짐을 확인하고 전 페이지 이미지로 검토했다. 증거 `evidence/rubric-*.png`.
- 과제 안내: 목표/액터/UI/ERD/API 일관성, 오류 흐름, Swagger 및 dbdiagram 구문 검증, 개요 PDF 안에 UI 흐름 포함.
- 예제 PDF 31쪽: 전체 이미지 개요 검토. 문제→해결→액터→전체 흐름→화면별 버튼/필드/API 주석→ERD→API 구조가 기준. 화면 없는 화살표 도식만으로 대체하지 않는다.
- API 예제: OpenAPI 3.0.3, 태그, requestBody, 응답 코드, 공통 Error와 $ref 재사용, 페이지네이션. 교육 도메인과 localhost 서버를 그대로 가져오지 않는다.
- DBML 예제: PK/FK, enum, 복합 unique, M:N 해소, 계산값 분리. 재응시 시 과거 답안을 지우는 예제 정책은 학습 이력 분석 목적에 맞지 않아 채택하지 않는다.

## 검증 범위

다섯 참고파일의 복사 SHA256 대조는 `evidence/reference-inventory.json`에 기록되어 있다. PDF 예제는 디자인 참고이고 제품 화면으로 복제하지 않는다. API 예제 전체 YAML 파싱을 실행하여 OpenAPI 3.0.3, 22개 경로를 확인했다. Swagger 렌더는 아직 검증하지 않았다.
