## 5. 목표 제품과 고정 요구사항

한국어로 1·2종 보통 운전면허를 준비하는 사람을 위한 웹 학습 보조 서비스야. 필기 학습·기본조작 연습·도로주행 시뮬레이션·로그인·이력 저장·공식 안내·AI 오답 해설과 통합 취약점 분석을 연결해. 공식 시험이나 실차교육을 대체한다고 주장하지 마.

- 최종 제품에서 가상 달러·빚·파산·임의 게임 벌점을 제외해.
- MPU-6050은 roll 조향만: LEFT=-1, CENTER=0, RIGHT=1. pitch 가속/후진은 사용하지 마.
- 중앙 보정과 히스테리시스 적용. 진입12°/복귀7°는 초기 제안값이며 실제 장치 검증 후 확정해.
- 셋업: 중앙 안정3초 → 좌 확인 → 중앙 → 우 확인 → 중앙 → READY → 명시적 시작. 전후 기울임 점검 없음. 좌우 부호 반전 지원.
- 키보드 모드는 W/S 전진·후진, A/D 조향이다. 센서 모드는 방향키 위/아래로 전진·후진하고 MPU-6050 roll로 조향한다. 서로 반대인 두 키를 함께 누르거나 아무 키도 누르지 않으면 정지/중앙이다.
- R은 셋업/주행에서 즉시 정지·입력·점검 상태를 초기화하고 다시 시작. 셋업은 CENTER/STOP을 표시하되 중앙 재측정 전에 READY로 표시하지 마. 텍스트 입력 중 R은 일반 문자로 처리해.
- 센서 단절·잘못된 입력·브라우저 포커스 상실은 정지/일시정지와 복구 경로를 제공해.
- Web Serial 지원 Chromium을 우선하고 실제 필요가 확인될 때만 로컬 브리지를 추가해.
- 정답은 검수된 문제 데이터가 결정하고 AI는 설명만 담당해.
- 채점은 현행 공식 근거에 맞춰 감점과 즉시 실격을 구분해. 전체 항목과 일부 하위조건 지원을 혼동하지 마. A만 자동 채점, B는 연습용 표시, C는 안내만 제공해. 구현 검증 전 A 후보를 활성화하지 마.
- 공식 자료·문항·채점규칙·코스 버전을 보존하고 과거 결과를 임의로 덮어쓰지 마.
- AI는 실제 저장된 답안/사건만 분석하고 출처를 제시해. 측정하지 않은 거울 확인·반응시간 등을 만들어내지 마.
- 비밀번호 안전 해시·서버 인증 세션·본인 데이터 권한 검사를 구현하고 비밀키를 프런트에 넣지 마.

## 바로 이어서 할 작업

1. 현재 서버가 5180·8010 포트에서 실행 중인지 확인한다.
2. 센서 화면이 여전히 45~51Hz의 WME 데이터를 받는지 실제 브라우저에서 확인한다.
3. 사용자가 센서를 움직일 수 있는 상황이면 중앙 3초 → 왼쪽 → 중앙 → 오른쪽 → 중앙 → READY 전체 흐름을 함께 검증한다. 물리 입력 없이 완료했다고 쓰지 마.
4. READY 뒤 센서 모드 주행을 시작해 MPU roll이 조향만 담당하고 방향키 위/아래가 전진·후진만 담당하는지 확인한다.
5. 센서 단절 시 즉시 정지·일시정지되고, 재연결 뒤 정렬 화면으로 안전하게 복귀하는지 확인한다.
6. 새 결함이 발견되면 `미니프로젝트1_ver(2)` 안에서만 수정하고 TypeScript 검사, Vitest, Vite 빌드를 다시 실행한다.
7. 기능 검증이 끝나면 필요할 경우 Three.js 동적 import 또는 manual chunk로 초기 번들 크기를 줄이되, 주행 동작과 화면 품질을 먼저 회귀 검증한다.

진행 보고에는 변경 파일, 실제 실행한 명령, 관찰한 값, 남은 미검증 항목을 구분해서 적어. 공식 시험을 대체한다고 표현하지 말고, 배포·푸시·외부 전송은 사용자의 별도 지시 없이는 하지 마.
