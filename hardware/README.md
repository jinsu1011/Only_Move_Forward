# 센서 핸들 (Arduino UNO + MPU-6050)

## 배선

| MPU-6050 | UNO |
|---|---|
| VCC | 5V (모듈 레귤레이터 사양 확인) |
| GND | GND |
| SDA | A4 |
| SCL | A5 |

## 출력

115200 baud, 50Hz: `WME,<경과ms>,<roll>,<pitch>,<yaw>`. 시작 시 약 2초 자이로 영점(`INFO,KEEP_STILL_CALIBRATING` → `INFO,READY`), 오류는 `ERR,<사유>`.

웹은 roll(좌우 기울기)만 조향에 쓴다. pitch·yaw 는 쓰지 않는다(아래 실측 기록 참고). 기존 프로토타입 형식 `roll,pitch` 도 인식한다.

## 민감도

roll 은 가속도로 계산해 손떨림·충격에 흔들린다. 펌웨어는 원시값을 그대로 보내고, 웹이 튐 제거·평활·유지 시간으로 보정한다(`web/frontend/src/input/steering.ts`). 프리셋과 세부 조정은 정렬 화면에서 바꾼다.

## 실측 기록 (2026-09-16)

실제 장치를 `/dev/cu.usbmodem101` 로 직접 읽어 측정했다. 브라우저가 아니라 시리얼 원시 출력 기준이다.

| 항목 | 측정값 | 판정 |
|---|---|---|
| 샘플 주기 | 20.0ms (50.0Hz) | 사양대로 |
| 정지 시 roll 잡음 | 표준편차 0.088°, 폭 0.47° (12초, pitch 2.4°) | 임계값의 1/30, 문제 없음 |
| 자이로 영점 | `INFO,KEEP_STILL_CALIBRATING` → `INFO,READY` 정상 | 동작 |

### 알아낸 것 — roll 안정성은 장착 각도에 좌우된다

`roll = atan2(ay, az)` 는 칩이 수평일 때만 안정적이다. 핀 헤더를 위로 세워 다는 현재 장착에서는
핸들을 돌리는 동안 칩 pitch 가 0°↔90° 를 오가고, 90° 에 가까워지면 분모가 작아져 자세를 유지해도
각도가 크게 흔들린다.

| 칩 pitch | 자세 유지 중 roll 변동폭 |
|---|---|
| 2~6° | 0.8 ~ 1.6° |
| 32° | 9.6° |
| 58° | 39.7° |
| 82~88° | **8 ~ 78°** |

"값이 너무 크게 바뀐다"는 체감의 원인이 이것이다. 고장이 아니라 축 특성이다.

**대응 (2026-09-16):** 둔감(LOW) 프리셋을 실측 기록으로 재조정했다(진입 18→20°, 유지 180→400ms).
그 기록의 최악 구간에서 헛조향이 2회 → 0회가 됐다. 대가로 25° 기울기 응답이 460ms → 680ms 로 느려진다.
보통·민감은 응답 속도를 지키려고 그대로 뒀다. 회귀 테스트는 `web/frontend/src/input/input.test.ts` 의
`LOW holds steady on the measured sensor jitter` 에 실측 구간을 넣어 고정했다.

**남은 근본 대책(미적용):** 펌웨어가 roll 과 pitch 를 함께 보내므로, 웹에서
`atan2(sin(roll)·cos(pitch), −sin(pitch))` 로 중력 방향을 복원하면 pitch 와 무관하게 안정적인
핸들 각도를 얻는다. 같은 기록으로 검증했을 때 pitch 85~88° 구간 변동이 8~78° → 1.2~3.8° 로 줄었다.
펌웨어·배선·장착을 바꾸지 않아도 되지만 조향 입력 경로와 정렬 절차를 함께 고쳐야 해서 제출 후로 미뤘다.
